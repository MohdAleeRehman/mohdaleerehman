## 🔧 REGEN Repairs

A repair lifecycle system designed around **preserving truth instead of overwriting history**.

```text
Initial QC Finding
        │
        ▼
Technician Verification
        │
        ▼
Actual Diagnosis
        │
        ▼
Resolution
        │
        ▼
Final QC
```

The system models the difference between:

> **What was originally found**

and

> **What was actually diagnosed and resolved**

This allows repair jobs to remain traceable from intake to final saleable status.

# 🧠 Engineering Principles

### `01` — Model the business before the UI

```text
Who?
What?
When?
Why?
Who owns it?
What happens next?
What can fail?
```

---

### `02` — Make state explicit

I prefer:

```text
created
   ↓
pending
   ↓
processing
   ↓
awaiting_action
   ↓
completed
```

over hiding important business logic inside random boolean flags.

---

### `03` — Don't destroy history

Operational systems need memory.

```text
Finding
   ↓
Verification
   ↓
Diagnosis
   ↓
Resolution
   ↓
Final Result
```

A database should not only tell you **what is true now**.

It should help answer:

> **What happened?**

---

### `04` — Build for operators

The person using the system shouldn't need to understand the database.

The UI should answer:

```text
┌────────────────────────────────┐
│                                │
│       WHAT DO I DO NEXT?       │
│                                │
└────────────────────────────────┘
```
